# Brand Radar｜顺序化开发任务

## 优先级说明

P0：作品控制与恢复的可信度问题，先处理。  
P1：主流程阅读、输入、修改和触摸体验。  
P2：查找、输出与真实使用验证。  
HOLD：需要实际需求或性能证据后再启动。

优先级不是对代码严重程度的安全评级。以下任务以代码行为与产品取舍排序；未完成运行复现的项目，应先复现再修改。每个任务的范围按依赖递进，整个列表不代表一次全部执行。

## B01｜让取消与转节点的提交语义一致

**优先级：P0；依赖：B00。**

代码入口：`ios/BrandRadar/Sheets.swift` 的 `CardEditor`、`RichContentEditor` 回调；`BoardStore.editCard`、`splitBlock` 的实际实现；已有编辑历史逻辑。

源码依据：转节点前会调用 `store.editCard` 提交本地草稿，顶部取消只 `dismiss()`。[E07、E09]

首选改法：将该动作明确为“保存并转为节点”。有未保存内容时说明会保存；提交和转节点共同形成一次可撤销操作，结束当前编辑会话。保存前取消不改变作品。普通编辑退出时对未保存改动提供明确处理路径。

若当前实现更适合局部编辑事务，可以采用，但只管理本会话字段；不要创建全应用通用事务平台，不以整张画布旧快照覆盖并发新内容。

验收：
- 改字后取消，重开还是原稿。
- 改字后保存，重开保留新稿。
- 改字后“保存并转为节点”，内容只提交一次，原稿与新节点关系正确；一次撤销还原该次操作应还原的内容。
- 改字后向下关闭面板，存在清楚的保存／放弃／继续选择。
- Agent 同时更新其他字段或其他卡片时，本地取消／撤销不会覆盖这些无关更改。
- 富内容原件和附件仍可访问，无孤立文件清理误删。

## B02｜放下后恢复关系与归属

**优先级：P0；依赖：B00，涉及编辑事务的部分跟随 B01。**

代码入口：`BoardStore.editCard` 的 archived 分支、`CardEditor` 恢复操作、`CanvasEditing.swift` 的删除／历史命令、`Models.swift` 的存储模型。

源码依据：放下卡片删除相邻 edges 和组内 cardIDs，恢复状态没有对称还原。[E07、E09]

改法：给“放下”保留足够的恢复信息；可以采用归档元数据或保留可过滤的图关系，但只选一种清晰方案。将“暂存方向”和“永久删除”的产品语义区分开。复用现有历史机制，避免维护两套互相矛盾的图状态。

恢复时只还原仍有效且没有冲突的连线／父组关系，避免重复 ID、悬空端点、多父组或循环。若父组被删除、另一个端点不存在或用户已重新归类，保留当前真实状态并报告未恢复项。

验收：
- 建立 A→B，B 属于 G；放下 B，再从已放下内容恢复，节点、连线、归属一致。
- 关闭并重开后再恢复，结果一致。
- 放下 B 后删除 A 或 G，恢复 B 不制造悬空关系。
- 放下／恢复／撤销／重做的组合不产生重复对象。
- 已有旧文档可以读取；没有记录的旧关系不凭空补全。

## B03｜统一选择对象与连续对话

**优先级：P1；依赖：B01、B02。**

代码入口：`BrandRadarApp.swift` 的工作区与 dock；`Sheets.swift` 的 `ChatSheet`；`BoardStore.selectedCard` 和发送入口；`InfiniteCanvas` 的真实 UIKit 工具栏回调。

改法：复用现有对象选择机制，将整画布、单卡和组映射为一致的 UI 上下文。发送时固定本轮目标；面板持续显示目标名称。将“继续改”接到实际展示的工具栏。保留后端／本地现有选择范围校验。

发送后不自动关闭对话。支持主动收起与查看改稿位置。修改滚动跟随：阅读旧消息时不被拉回底部，用户在底部时继续跟随。

验收：选一张卡连续改三轮，无需重新找到输入入口；选组时明确显示组名；发出请求后选择变化不改变已发请求范围；目标消失时不扩大作用范围；旧消息阅读不被新回复打断；停止与失败不清空未提交草稿。

本任务不新增原生 AI 多选协议，不以聊天升级为名重做消息系统。

## B04｜整理输入入口与语音状态

**优先级：P1；依赖：B03。**

代码入口：`BrandRadarApp.swift` 的 `chatDock`、`beginDockVoice`、`endDockVoice`、`interruptDockVoice`；`HoldToTalkControl.swift`、`SpeechInput.swift`、`ChatSheet` 的语音输入。

改法：明确可点击的文字输入和麦克风；普通听写结束后先进入可编辑草稿。Beta 下沉为明确选择的高级入口，保留原有确认与恢复。避免把“打字／语音”“整理／发散”“普通／实时”同时做成常驻控制组。

验收：首次使用者无需说明便能找到打字入口；拒绝录音权限后继续打字；识别到错误词可以修改后发送；离开页面、中断、锁屏后的文字可恢复；Beta 待确认重启保留，放弃不会抹去手改。

需要比较的取舍：普通听写多一次发送动作能否接受。记录真实使用反馈，不将个人偏好自动写成所有用户的固定设置。

## B05｜先能读，再微调画布美观

**优先级：P1；依赖：B03，布局与 B04 一致。**

代码入口：`InfiniteCanvas.swift` 的 `drawCard`、`drawGroup`、`drawEdge`、`fit`、`updateToolbar`；`CanvasRichPreview.swift`、`CanvasGeometryCache.swift`；新增或复用卡片阅读页。

改法：实现远／中／阅读三级展示。普通正文不以缩到不可读的小字填满全貌。阅读入口使用正常排版并保留原始内容；返回时恢复视角。优先复用当前编辑器的内容组件做只读展示，不一次建设完整文档编辑系统。

验收：小画布和 30／120 节点样本都能通过可见入口阅读全文；长中文标题不与状态重叠；表格与清单预览保持；同一节点切换层级不会移动；返回画布不迷失；屏外剔除仍有效。性能记录与原基线比较，不能以删掉富内容或历史功能换取帧率。

## B06｜可定位、可撤销的改稿结果

**优先级：P1；依赖：B03、B05。**

代码入口：`BoardStore` 的运行会话／实际应用差异、`CanvasEditing.swift` 的条件撤销、`InfiniteCanvas` 的 `newIDs`／`locateNew`、工作区结果提示。

改法：基于实际变化产生轻量结果条，覆盖修改、增加和放下；支持查看目标与撤销本轮。复用现有会话历史，避免另造独立的“AI 历史数据库”。普通 Brief 不强制逐轮审批。

验收：只修改旧卡时仍能定位；没有新增时不显示错误的新增数；部分失败区分已应用与未完成；查看变化不会覆盖当前编辑，返回能回到刚才位置；撤销本轮保留无关手改；Beta 原有保留／放弃保持一致。

## B07｜统一视觉细节与操作命中区域

**优先级：P1；依赖：B03—B06 的结构基本稳定。**

代码入口：`Sheets.swift` 的 `RadarPalette`、`BrandRadarApp.swift`、`InfiniteCanvas.swift`、`RichContentEditor.swift`；Web 只在必要时做同语义对齐。

改法：统一 SwiftUI／UIKit 颜色来源，建立少量间距、字级、边框和圆角 tokens；扩大高频点击区域；清除无意义的重复小字；保留卡片类型和来源语义。撤销／重做与当前工作有关的动作优先于连接设置。保留系统字体与暖纸色，不增加新字体文件或图像资产依赖。

验收：真实渲染的普通、选中、编辑、失败、禁用状态均采集对照；有效点击区域符合 44×44 点起始要求；字色对比经过计算；大字体、VoiceOver、减少动态效果检查通过或明确记录待修项。不能只改色值就宣称 UI／UX 完成。

## B08｜找回旧稿与当前归档

**优先级：P2；依赖：B02，B05。**

代码入口：`BoardLibrary`、`BoardStore.visibleBoards`、`RadarBoard.updated`、当前画布的归档入口。

改法：原生画布库增加最近修改排序、时间和简单的标题／正文搜索；当前已放下内容从全局画布库移回当前画布。复用内存中文档，无外部搜索服务。搜索查找内容不修改原文和更新时间。

验收：至少 12 张隔离样本中能找到目标画布；搜索无结果、清空、进入目标、返回列表均清楚；演示与真实作品继续隔离；归档恢复走 B02 的安全路径。

暂缓文件夹、标签、跨文档知识图谱、置顶与团队权限。

## B09｜输出一份能在画布外继续阅读的工作稿

**优先级：P2；依赖：B05、B08；根据真实使用决定是否立即启动。**

代码入口：`CanvasExport.swift`、`RadarSource`、`CardEditor` 分享入口；Web 已有 HTML／Markdown 导出实现作为行为参考。

先检查现有 PNG、PDF、可编辑包和单卡分享。若大画布导出缩小后难以阅读，再补一个最小的“按当前分组顺序阅读”输出，首选文本／Markdown 或分享可读文本，不立即建设多版式报告引擎。

要求：保留标题、当前有效正文与可用来源链接；注明只有链接或用户提供材料等真实状态；排除已放下内容或明确选项；相同对象不重复输出；不输出密钥、连接配置或隐藏私人记录。图片参考来源与商业授权的含义不能混淆。

验收：一份导出的工作稿可在画布外阅读；顺序可解释；来源可追溯；附件包往返仍通过；导出失败有真实提示。新增格式以真实需要为启动条件，不因为格式清单显得完整而增加。

## B10｜真人语音与容量验证

**优先级：P2／持续验证；依赖：B00 后可开始，B04／B05 后复测。**

代码入口：`SpeechInput.swift`、`AgentStreamGeneration.swift`、`BoardStore.persist`、`CanvasGeometryChecks` 和已有 UI 回归。

语音：连续 60—90 秒真人口述，包含停顿、改口、否定和分组；分别检查权限拒绝、锁屏、应用切换、来电／音频中断、取消、尾部补完与重开。记录“首段文字”“首个可用节点”“尾部完成”三个时点，不混成一个速度数值。涉及真实模型的测试需显式控制凭据与调用成本。

容量：3／30／120 节点，少量与较多附件，1／12／50 张本地文档分别记录打开、阅读、拖动、保存、重开及内存。说明设备、构建、样本、次数；测量次数不足时不给稳定分位数结论。绘制探针与整机交互耗时分开记录。

只在发现重复出现的实际瓶颈后，启动有证据的局部优化。无证据时不改存储引擎、不替换渲染器、不删历史、不扩大模型上下文工程。
