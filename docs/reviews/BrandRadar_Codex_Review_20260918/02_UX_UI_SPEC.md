# Brand Radar｜UI／UX 修改规格

本规格是设计提案。尚未取得本轮页面截图，所有布局需在实际渲染后检验。优先复用已有组件和系统行为，不引入新的视觉技术栈。

## 1. 工作区的信息结构

保持一张主画布。顶栏负责文档身份和离开／返回；底部负责表达；选中后的工具栏负责当前对象。所有能力围绕当前作品出现，避免同时铺开工具面板、状态日志和配置。

### 顶栏

显示当前画布标题及画布库入口。保存失败时给出明确状态；正常保存状态保持低干扰。撤销／重做在编辑期间有直接入口，按钮禁用状态须能理解。更多菜单容纳重命名、整理、当前画布的已放下内容、导出和设置。

连接设置在未配置或连接失败时需要明显入口；连接正常后，常驻天线图标可以退到更多菜单。一次更改无需同时重做全部导航。

### 默认底部输入

空闲态露出明确的可输入区域，例如“补一句想法，或选中卡片继续改”，旁边提供带可访问名称的麦克风。短按输入不需要发现隐形手势。长按听写可保留为快捷方式，但不能成为唯一入口。

有选择时，在输入区顶部显示：

- `正在讨论：整张画布`
- `正在修改：〈卡片标题〉`
- `正在修改：〈分组标题〉 · 4 张卡片`

分组数量必须说明是否包含子组，并采用一致计算方式。目标不存在时提示重新选择，不能悄悄扩大为全画布。

“整理表达”与“展开想法”属于可选意图提示；用户仍可直接用自然语言表达。只有当两种模式确实改变服务端／本地 Agent 行为且有测试时，才展示对应开关。不要先加一个没有真实语义的控件。

### 模板

保留六套现有模板，不扩充数量。入口文案明确表示“新建画布”，避免被理解成给当前画布换模板。空画布以直接写入为主，模板与示例为辅助入口。

## 2. 连续对话

发送成功后保留面板状态，不强制退出聊天。发送失败时保留原文字，允许编辑重试。进行中的请求禁止重复提交，停止后保留已应用部分。

优先使用可收起、可展开的系统面板或现有底部区域。只在确有阅读需求时展开更多聊天区域；画布可见范围随面板实际高度计算。关闭键盘和关闭面板应是不同操作。

对话列表只在用户接近底部时跟随新内容。用户向上阅读时，保持位置并提供“有新回复”按钮。参考实现可以用底部哨兵的可见性判断，避免固定内容高度假设。

收起后再次打开，恢复草稿及合理的阅读位置。切换画布时，各画布草稿分开；未发送文字不会串到下一份作品。

## 3. 普通听写与实时 Beta

### 普通听写的建议默认行为

点麦克风或按住开始 → 显示转写 → 结束收音 → 转写回到可编辑输入框 → 用户发送。

这会比现有“松手直接提交”多一步，但能降低专有名词、否定词和识别错误直接改动画布的风险。熟练使用者的“松手发送”可以作为明确开启的选项保留，暂不要求新增设置项；优先在本轮真实使用中比较两种流程。

权限请求应发生在用户主动使用麦克风时。拒绝权限后，文字输入继续可用，并在录音入口附近显示原因与处理路径。中途离开、锁屏或来电时，已识别文字作为草稿保留，不以空结果覆盖。

### 实时 Beta

Beta 是可选的边说边成图入口，不与普通工作流争夺默认主位。现有逐段变化、松手补尾、保留／放弃及重启后待确认必须保留。

区别显示“已完成收音”与“仍在整理尾部内容”。不能因为麦克风已停止，就让用户误以为所有画布变化已完成。

人手动修改了某处内容后，放弃 Beta 的结果应继续沿用已有条件撤销逻辑，保留人的后续改动。不要使用整个画布快照的无条件替换。

## 4. 普通 Agent 改稿后的反馈

复用保存层已有差异／会话信息，生成轻量的结果条：

> 已修改 2 张，新增 1 张　查看变化　撤销本轮

这里的数量是界面示例，实际必须来自已应用到作品的修改集。运行失败但已完成部分结果时，写明“已保留的部分”和“未完成的部分”，不要整轮标成成功。

“查看变化”可逐张定位，显示修改对象标题；必要时展开简短前后文本。初期无需复杂版本树或全量差异编辑器。普通 Brief 保持直接执行与可撤销，不强制为每条输入增加审批步骤。

正在阅读旧卡、编辑文本或手动拖动时，模型新增内容不会强制改变相机。需要跳转时由用户点击。跳转前保存一个临时返回位置，支持“回到刚才”，不无限积累导航历史。

## 5. 选中、阅读与编辑

保留现有单击选中、再次点击展开等已经修复过的手势。先增加可见的“阅读／编辑／继续改”路径，再评估是否需要改变手势，不同时重写单击、双击、长按和连线识别。

单选对象后，主动作优先为“阅读”“继续改”以及一个对象工具入口；复制、连接、删除可放在次级菜单。也可继续复用现有工具栏，但高频动作不应全靠图标记忆。

阅读状态以完整内容为主，标题、正文、来源和采用状态可见。标题及正文默认按正常字号排版，不随画布比例缩小。编辑动作进入现有编辑器；清单勾选、单元格编辑等已有读优先行为保留。

返回画布恢复原来的视角与选中对象。当前阅读的卡被放下或移除时，有明确提示和回到画布路径；不能继续编辑一个已不存在的悬空副本。

## 6. 编辑器的提交规则

采用一致且可解释的规则：普通文字／颜色／采用状态修改先进入当前编辑草稿；点击保存才提交。脏草稿向下关闭或退出时提供“保存／放弃更改／继续编辑”，没有更改时直接退出。

“保存并转为节点”是明确的提交动作。确认后提交原卡修改与转节点操作，结束当前编辑会话；保留一次撤销入口。不要让用户执行该动作后仍停留在一个写着“取消”但已无法取消前面变化的会话中。

实现时继续采用字段级或内容块级合并。若 Agent 同时修改了同一字段，应提示冲突或保留可恢复版本；不直接以旧副本覆盖全部新内容。单独修复提交语义，不顺带重构所有富内容组件。

## 7. 画布缩放与阅读层级

### 远景

主要看分组、方向和对象分布。隐藏不可读正文、缩略操作提示和过密连线标签。极远处可只保留有区分力的组标签和形状；可阅读内容交给聚焦或阅读状态。

### 中景

显示标题和简短预览，保留必要状态。预览来自现有内容，默认不触发额外 AI 摘要调用，也不悄悄改写正文。长标题截断时，阅读入口能看到全文。

### 阅读状态

正文建议从系统 body 大小（约 17 点的默认层级）起步，再按实际中文材料测试。辅助信息建议 12—13 点，不能把关键正文降到辅助层。以上是本产品提案，不是声称标准要求这些具体字号。

阈值应考虑实际显示字号、卡片屏幕尺寸和可见区域，不只检查卡片宽度。维持现有几何模型与屏外剔除；新增不同层级不会引起节点位置变化、组框跳变或每帧重测长文。

“查看全貌”继续存在，承担结构浏览。全貌不承担全文阅读责任。首轮无需新增完整目录树；基础阅读入口做好之后，再按实际查找需求加入线性内容视图。

## 8. 视觉 tokens 与内容层级

### 继续沿用的气质

暖白底、墨绿动作、轻纸张层次、克制的低饱和辅助色。让它接近可持续阅读的工作桌面，不追求科技大屏、玻璃浮层堆叠或满屏彩色卡片。

当前 SwiftUI `RadarPalette` 与 UIKit 画布背景使用了不同的近似颜色。统一来源后，再观察是否需要微调。不要为了“更高级”更换整套色盘。

| token | 起始建议 | 用途 |
|---|---|---|
| `canvasBackground` | 优先复用现有 `RadarPalette.canvas` | 主桌面底色 |
| `paperSurface` | 复用现有 `RadarPalette.paper` | 阅读和卡片表面 |
| `accent` | 复用现有 `RadarPalette.green` | 主动作、选中、焦点 |
| `textPrimary` | 单一深墨色语义 token | 关键标题和正文 |
| `textSecondary` | 实测合格的次级墨色 | 来源、日期等辅助信息 |
| `borderSubtle` | 单一细边框 token | 静态纸张层次 |
| `focusBorder` | 以屏幕可见尺寸校准 | 键盘焦点与对象选择 |

布局间距建议采用 4／8／12／16／24 点系列，圆角形成卡片、面板、按钮三档，避免每个局部独立选择。不要机械地把所有间距和圆角变成同一个数值。

### 字体与细节

使用平台系统中文／拉丁字体组合。正文以可读为先；大段中文不加装饰性字距。英文品牌标记可保持小型装饰层，但关键操作和状态不能使用同样的小字号。

标题、正文、来源之间通过字重和留白形成区别。删除重复的英文 eyebrow 或解释性尾句时保留有用的中文类型信息。来源数量与采用状态可成为辅助行，内容不需要每张都出现一句“可继续推敲的方向”。

纸张阴影只帮助识别层次，选中主要通过边框／状态表现。连接线在选中相关方向时提升强调，其余保持低干扰，但仍需可见。动画保留现有减少动态效果支持，避免每轮生成同时发生平移、缩放、弹跳和高亮。

### 颜色语义

保留用户自由配色；卡片颜色可用于个人归类。类型、采用状态、错误、选中等重要含义都通过文字或图标补足。不要仅凭绿色暗示内容已核实，也不要用颜色替代来源依据。

## 9. 无障碍与触摸细节

以 Apple 44×44 points 作为原生高频点击区域的起始要求。视觉图标可以小于点击区域；检查相邻区域不重叠，工具栏扩大后不遮挡对象。[E16]

关键文本与背景按实际色值测量。Web 普通文字参考 WCAG 4.5:1、大字 3:1；原生也可采用相同对比度目标作为设计检查，但这不构成无障碍认证。[E16]

继续保留已有卡片、分组和关系的 VoiceOver 元素。给“发送”“麦克风”“撤销本轮”等动作提供明确名称；分组提示“展开”时应执行展开，若只是聚焦则文案写“聚焦分组”。检查焦点顺序、面板关闭后焦点恢复、系统大字体、减少动态效果和纯键盘操作。截图无法证明这些行为。

Web 检查 200% 文本缩放时主要工作流程仍可用；原生检查实际 Dynamic Type 档位，不把两者记为同一项测试。

## 10. 找回旧稿与已放下内容

画布库第一批只增加：最近编辑排序、日期和标题／正文搜索。沿用已有文档模型，不建全文搜索服务。结果显示命中的画布与一段摘要；点击进入正确对象或画布，关闭搜索恢复合理位置。

当前画布的“已放下”单独放在当前文档操作里。恢复后展示恢复了什么、哪些原关系因对象缺失而未恢复。不要在全局画布列表里插入当前某张画布的卡片。

置顶、文件夹、跨文档链接与标签系统暂缓。先验证十余张画布的日常查找，再考虑进一步组织能力。

## 11. 空白、加载、失败与异常文案

| 状态 | 需要告诉用户的事 | 可执行动作 |
|---|---|---|
| 空画布 | 可以直接写第一段想法 | 输入；模板作为次级入口 |
| 尚未配置模型 | 本地画布仍能写；AI 暂未连接 | 去配置；继续手动写 |
| 模型处理中 | 当前正在整理／修改什么 | 停止；继续阅读已有内容 |
| 已有部分结果，后续失败 | 哪部分已保留，哪里未完成 | 查看保留结果；编辑重试 |
| 仅讨论，无画布更改 | 本轮回复在对话中 | 继续追问；关闭 |
| 保存失败 | 当前内容尚未可靠保存 | 重试保存；先导出可恢复副本 |
| 语音被打断 | 已转写的文字仍在草稿中 | 继续编辑；重录 |
| 找不到搜索结果 | 当前查询没有匹配内容 | 清空查询；回到全部画布 |
| 来源只有链接 | 链接已保存，尚未读取原文 | 打开原文；补充正文 |

文案应基于真实能力与状态。例如只有链接时不显示“已查证”；模型已停止时不继续显示“处理中”；导出失败时不发成功提示。不要增加持续出现的可靠性宣言。

## 12. Web 保留入口的有限优化

已有 Web 代码包含最近更新排序、保存状态、来源与多选讨论等功能，原生缺项不能直接套到 Web。[E14—E15]

本轮 Web 最多处理三类对齐：减少卡片重复装饰文字，统一保存／错误与来源状态的术语，以及检查窄窗口阅读与键盘操作。网页布局、调色与移动端不必完全相同。除非阻塞现有实际任务，暂不重排全部 Web 面板、替换 React 画布或追平原生富内容功能。
