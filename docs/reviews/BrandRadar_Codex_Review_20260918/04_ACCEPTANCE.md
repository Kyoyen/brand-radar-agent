# Brand Radar｜验收与截图矩阵

## 执行状态

**本矩阵是交给 Codex 的测试计划，尚未在本轮执行。** 仓库已有验收记录属于对应历史版本。本轮没有获得应用截图，没有完成 Xcode 构建、真实模型调用、模拟器或真人真机验证。

每次执行记录当前 commit、设备／操作系统、构建方式、测试数据版本、日期、具体步骤、预期与实际结果。状态只使用：`通过`、`失败`、`未执行`、`不适用（附原因）`。

## 隔离样本

### F1：关系与归档

3 张卡 A、B、C；A→B、B→C；B 位于分组 G。B 带正文、一个来源引用、一张图片和一段清单。保存基线 JSON 的对象与关系 ID，用于比较。另建包含子组的变体。

### F2：编辑提交与并发

一张含标题、正文、清单、图片的卡；另有无关卡 U。模拟人修改标题、Agent 修改另一字段或 U、用户转内容块为节点等交错顺序。只在隔离数据中模拟，不连接个人真实任务。

### F3：阅读与布局

3、30、120 节点三组样本，包括短标题、长中文标题、长正文、表格、清单、缺失缩略图、嵌套分组和距离较远的节点。覆盖窄屏、系统较大字体和底部面板展开状态。

### F4：查找与存储

12 张标题不同的画布，其中 3 张正文含同一关键词，设置不同更新时间；再生成 50 张容量样本。示例模式与实际模式各有同名画布，检查隔离。附件使用公开合成样本，不含个人材料。

### F5：真人语音

使用真实口述，内容包括：两个并行方向、一个共享材料、一次否定改口、一段停顿和一次只修改旧卡的指令。录音是否保存须由执行者明确选择，默认只记录结果与必要测试信息，不上传原始个人语音。

## 两个真实任务的使用记录

建议选择一项真实品牌小企划和一项真实内容构思，分别使用同一份工作稿多次。最初可由产品本人使用，再邀请 2—3 位相近使用者观察；这只是探索样本。

记录五个问题：开始表达是否费劲；阅读是否依赖反复缩放；连续修改是否重找对象；能否解释 AI 改了哪里；第二天是否自然接着使用。

首个小版本的通过条件应包括：A01—A08 不出现作品结构或提交语义错误；至少一次完整的“打开旧稿—连续两轮修改—恢复—关闭重开”工作可完成；未完成真机语音验证时，Beta 保持可选，不提升为默认承诺。
