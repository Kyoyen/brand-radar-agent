# Brand Radar｜作品集证据契约

更新日期：2026-08-31

状态：生效

## 目的与边界

本项目需要积累可用于个人作品集、简历和面试的证据，但职业展示不是产品 MVP 的目标。产品范围由 `docs/product/PRD.md` 决定；本文件只规定什么已经能够证明、何时可以升级表述，以及需要保存哪些材料。

## 作品集要证明什么

招聘者应能在二十秒内看懂：

1. 这是一个面向营销企划的品类情报 Agent，不是通用聊天机器人。
2. 项目把分散信号变成统一 Feed、日历、关键词和 Brief。
3. 设计重点是 Agent 筛选、证据链、失败边界和可回放评测。
4. 项目当前做到哪里，哪些仍在计划或开发。

面试时应能回答：为什么从多场景框架收敛、为什么 Replay-first、如何定义 Agent、如何处理小红书 / 抖音数据边界、如何验证聚类与 Brief、如何区分产品目标和求职目标。

## 证据成熟度

### A｜规划与工程基线（当前）

必须存在：

- 公开 GitHub commit。
- 产品 PRD、产品 Roadmap、Agent 执行目标和 Mac Mini handoff。
- V4.2 代码中可核查的多模型适配、工具调用和结构化输出。
- README 中清楚区分已有与未实现。

当前安全表述：

> 将早期多场景营销 Agent 原型收敛为面向营销企划的品类情报工作台；完成瑞幸 / 现制咖啡 MVP 产品契约、证据链与 Agent 行为设计，并基于已有多模型、工具调用和结构化输出基线进入 Dashboard 实施准备。

不能写：已完成 Dashboard、已全网监测、已稳定抓取社媒、已带来提效或已被品牌采用。

### B｜Replay MVP

升级表述前必须存在：

- 无密钥启动记录和固定 Replay 数据。
- 15+ SourceDocument → 5–10 Cluster 的实际输出。
- Feed、日历、关键词和 Brief 的真实界面截图或短视频。
- 重复合并、无关降权、单源待核和敏感日期暂停的 bad-case 结果。
- 端到端测试、启动命令和 commit。

通过后可写：

> 独立设计并实现品类营销情报 Agent MVP，将多来源材料标准化为可追溯信号簇，并通过 Dashboard 支持竞品观察、营销日历、关键词发现和 Brief 生成；以固定 Replay 和 bad-case 回归验证去重、排序、待核与人工确认边界。

### C｜Live public

升级表述前必须存在：

- 至少一个真实公开来源的运行记录、URL、发布时间和抓取时间。
- 来源失败 / 部分成功界面。
- Replay 与 Live 的同屏区分。
- 不含登录绕过、内部数据或未授权社媒抓取。

通过后可以增加“接入公开来源刷新”，仍不能写“全网实时监测”。

### D｜真实使用与效果

任何效率、采用、稳定运行或业务结果表述都必须同时具备：

- 明确用户和任务样本。
- 改造前人工基线与改造后测量方法。
- 样本量、时间窗口、失败记录和统计口径。
- 用户反馈或真实使用记录。
- 结果可归因边界。

缺少任一项，不使用 1/20、节省 X 小时、零值守、替代人工或生产采用等表述。

## 每个里程碑保存的证据

|类型|最低证据|
|---|---|
|产品判断|PRD 变更、取舍记录、反目标|
|工程能力|关键代码、Schema、Prompt 版本和架构说明|
|运行|精确命令、exit code、数据模式和时间|
|Agent 质量|bad-case 输入、前后输出和判断规则|
|界面|真实渲染截图、标准三分钟路径和空 / 错误状态|
|Live 来源|URL、published_at、fetched_at、失败状态|
|版本|branch、commit、PR / diff 和干净状态|
|限制|未完成项、数据边界和人工确认点|

截图、短视频和示例必须来自实际运行。静态设计稿可以展示产品方向，但需要明确标为 Concept / Prototype。

## 公开仓库规则

- README 先写当前事实，再写目标能力。
- Replay / Manual / Synthetic 与 Live 显式区分。
- 示例中的品牌、数字、热度和外发状态不得伪装成真实。
- 第三方壳、组件、数据服务和视觉资产保留 License 与来源。
- 不公开 API Key、Cookie、内部材料、付费内容、个人数据或平台登录态。
- 历史探索可以保留在 Git，但默认入口只指向当前产品。

## 简历与发布闸门

仓库更新不等于自动更新简历、LinkedIn 或公开作品集页面。每次升级个人材料前需要：

1. 重读最新 `docs/PROJECT-STATE.md`。
2. 将目标表述映射到本文件的成熟度等级。
3. 打开相应 commit、运行证据和界面，而非依赖执行者自述。
4. 检查“参与 / 负责 / 独立 / 主导 / 上线”是否符合事实强度。
5. 单独取得用户发布确认。

## 禁止的作品集捷径

- 以 PRD 页数、Agent 数量或界面精美度代替可运行闭环。
- 把旧 presentation、Mock 样例或代码注释当成新 MVP 证据。
- 使用不存在的客户、采用、发送、投放或提效数字。
- 将第三方 Agent 壳的基础能力表述为自研。
- 省略失败、限制和人工确认，只展示理想路径。
