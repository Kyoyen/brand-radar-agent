# Brand Radar｜Agent 执行与工程目标契约

更新日期：2026-08-31  
状态：目标契约已建立；等待 Mac Mini 项目登记后开始实施

## 文档边界

这里同时约束两类 Agent：

1. **产品内营销 Agent**：Brand Radar 在每次情报运行中必须怎样判断和输出。
2. **工程执行 Agent**：Mac Mini 上的 Codex 如何把 V4.2 基线改造成已批准的 MVP。

产品价值和 MVP 范围以 `docs/product/PRD.md` 为准；本文件不允许执行者重新扩大产品目标。

## 目标方向

- 服务对象与情境：每天需要扫描竞品、节点、热点和风险的营销企划人员。
- 要改变的产品状态：从宽泛多场景 CLI 原型，变成一个以瑞幸 / 现制咖啡为可复跑案例的营销情报 Dashboard。
- 要改变的工程状态：从缺少统一领域模型、Replay、聚类、界面和测试，变成可安装、可运行、可回放、可追溯、可独立验收的 MVP。
- 更大目的：形成一个真实可用的营销 Agent 小工具，同时留下可经受面试追问的产品决策与工程证据。

## 产品内营销 Agent 的执行目标

### 输入

- BrandProfile：品牌、品类、地区、时间窗口、受众、关注方向。
- 用户确认后的竞品观察名单。
- Live / Replay / Manual 来源及营销节点配置。

### 运行主线

```text
理解观察面
  → 扩展检索词与来源
  → 采集并标准化 SourceDocument
  → 提取 MarketingSignal
  → 去重并聚合 SignalCluster
  → 评估相关性 / 新颖性 / 时效 / 证据 / 风险
  → 必要时补证、降置信或停止
  → 输出 Feed / Calendar / Keywords / Brief
```

### 必须行为

- 主动筛掉弱相关噪声，不把来源列表直接交给用户。
- 合并同一 Campaign 的多来源表达，保留完整证据列表。
- 单源低可信、来源冲突和高风险内容进入待核或人工确认。
- 事实、推断和建议分层；生成字段引用有效 ID。
- 输出 `why_now`、机会角度、风险和未知，不只做摘要。
- 高热但弱相关的信号可入库但降权，并解释原因。
- 敏感日期与促销 Brief 冲突时暂停该 Brief。

### 表达契约

- 角色：资深营销情报编辑 + 企划助理。
- 顺序：结论 → 为什么是现在 → 证据 → 机会角度 → 风险与未知。
- 推荐开场：`今天新增 8 个值得关注的营销信号，优先看这 3 个。`
- 禁止客服腔、虚构全网覆盖、无来源数字和最终法律判断。

### 可观察执行证据

- 每次运行记录 Prompt / 规则 / Schema 版本、数据模式、来源状态和处理数量。
- 每个 Cluster 可追溯到 SourceDocument。
- 每个 Brief 可追溯到 Signal / Cluster。
- bad-case 回归能观察合并、降权、待核和人工确认的实际分支。

## 工程执行 Agent 的目标

### 完成态

#### 结果证据

- 用户能在三分钟内完成瑞幸标准路径：确认观察面 → 找到优先信号 → 查看证据 → 生成 Brief 角度。
- Replay-first 的 Dashboard 在无 API Key 环境可重复运行。
- 至少一个 Live public 来源真实刷新；失败状态可见。
- 更换品牌、地区、关键词或竞品名单无需改代码。

#### 交付证据

- 稳定的本地启动入口与 README。
- BrandProfile、SourceDocument、MarketingSignal、SignalCluster、BriefSuggestion、Feedback Schema。
- 固定瑞幸 Replay fixtures 和 bad-case 集。
- 统一情报流、日历、关键词和 Brief Dashboard。
- 版本化 Prompt、工具说明、排序规则和输出 Schema。
- 变更相关测试、至少一条 MVP 端到端测试及可复核运行样例。
- 更新后的项目状态、截图 / 短演示和跨设备 handoff。

#### 验收方法

- 新环境按 README 从 Git clone 开始复跑。
- 运行固定 Replay 并检查 PRD 的数量、引用、筛选和风险验收项。
- 运行 bad-case，确认重复合并、无关降权、单源待核和敏感日期暂停 Brief。
- 人工在 Desktop 页面完成三分钟任务流。
- 另一位 Agent 复核代码、测试、界面、来源和公开表述。

## 反目标与错误捷径

### 不追求

- 通用全网舆情平台、多 Agent 编排展示或完整社媒覆盖。
- 自动发布、自动投放、无人监管的外部动作。
- 在 MVP 前完成模型微调、组织权限或多租户。
- 为作品集好看而先做空心 Landing Page。

### 禁止的伪完成

- 把旧 V4.2 CLI 或静态 presentation 当成新 Dashboard。
- 把 Mock、Replay 或 Synthetic 数据展示为实时抓取。
- 只生成五到十张卡片，却没有去重、证据链和 Agent 筛选。
- 使用写死输出通过演示，却无法更换筛选条件。
- 以自述、截图或 README 代替运行和测试。
- 用未经验证的 1/20、工时节省、生产采用或真实发送证明价值。

## 边界与权限

### 可以

- 在本仓库新增和修改 MVP 所需代码、文档、测试和公开 Replay 数据。
- 评估并依法复用开源 Agent / UI 壳。
- 接入无需登录、可稳定访问的公开来源。
- 在本地或 Mac Mini 上重建依赖、运行测试和生成非敏感演示资产。

### 必须保留

- V4.2 历史通过 Git 可追溯，不以破坏性重写删除。
- Live / Replay / Manual / Synthetic 边界和来源字段。
- 人工确认、失败状态和证据缺口。
- 第三方 License、NOTICE 和实际依赖说明。

### 需要额外授权

- 新增付费数据源、云部署、外部发送、自动调度或公开生产 URL。
- 处理登录态、企业内部数据或个人信息。
- 改变 GitHub 仓库可见性、许可或默认分支保护。
- 更新简历、LinkedIn 或向招聘方发布。

### 不能

- 绕过平台登录、风控、robots 或服务条款限制。
- 提交密钥、Cookie、浏览器配置、Keychain 数据或运行数据库。
- 强推默认分支、运行遗留强推脚本或覆盖不明 WIP。
- 输出最终法律结论或未经证实的品牌事实。

## 取舍顺序

`真实与可追溯 > 最小产品闭环 > 可复跑 > Agent 判断质量 > 视觉完成度 > 功能广度 > 开发速度`

## 工程里程碑

### M0｜诚实基线与远端就绪

- 状态变化：GitHub 包含产品、执行、作品集和 handoff 入口；Mac Mini 能克隆并完成安全 smoke。
- 证据：commit、干净状态、依赖安装记录、`--help` / `--list` 输出、远端项目登记。
- 停止：远端 SHA 不一致、秘密泄露、依赖安装超时或项目无法登记。

### M1｜领域数据与 Replay

- 状态变化：固定材料变成可查询的 Source / Signal / Cluster 数据链。
- 证据：Schema 测试、15+ 来源材料、5–10 Cluster、重复合并和引用验证。
- 停止：来源不可公开、引用链不成立或 Replay 被误标为 Live。

### M2｜营销 Dashboard MVP

- 状态变化：统一 Feed、日历、关键词和 Brief 共用观察面与证据链。
- 证据：可交互页面、筛选测试、三分钟人工验收和端到端测试。
- 停止：界面进度挤占数据真实性，或页面只能展示写死样例。

### M3｜Agent 壳与回归

- 状态变化：Prompt、工具、排序、Schema 和模型 Adapter 可版本化、比较和回退。
- 证据：bad-case 结果、版本差异、失败定位和回退记录。
- 停止：改动无法解释，或为了通过评测降低验收门槛。

### M4｜Live 与作品发布

- 状态变化：至少一个真实公开来源进入同一链路，作品集证据与实际能力一致。
- 证据：Live 来源记录、失败状态、最终截图 / 演示、README 和独立复核。
- 停止：来源不稳定两次、必须越权访问，或公开表述超过证据。

## 阻塞与升级

以下情况立即停止当前分支并报告：

- 同一安装、来源或远端连接问题连续两次失败。
- 单次长操作超时，或依赖 / 构建不确定分支超过五分钟。
- 需要用户选择会显著改变数据合法性、公开范围、成本或产品切线。
- 测试或真实页面无法支持准备公开的能力声明。

普通局部未知写入 `docs/PROJECT-STATE.md` 后继续；不得以“有计划”冒充已完成。
