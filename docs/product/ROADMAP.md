# 从网页 Demo 到企划 App

Brand Radar 想成为一位有品牌记忆、能一起推敲作品的企划搭档。主要产品形态是一款封装好的 App；网页端也会保留，作为另一种使用入口。当前先把日常使用的体验做出来，不急着部署在线服务。

## 现在：用可运行的 Demo 找到合作的感觉

目前的网页 Demo 已连接真实模型，能读取与补充公开材料，留下观察、创意和问题；人可以选卡追问、直接修改、保留或放下方向，并从历史继续、导出工作稿。

这张桌面用于探索交互和打磨 Agent，界面与使用方式还会变化。当前没有 App 安装包，也没有面向公众的在线服务。

贯穿案例为“上海周末，咖啡该出现在什么时候？”。我们用真实作品检查它有没有读懂材料、有没有品牌参与的理由，以及反馈之后能不能改到方案本身。原有 Replay 周会稿保留为历史回放入口。

## 接下来：让人愿意每天打开它

**把工作收进 App。** 安装、打开，就能回到自己的企划桌面；模型连接与常用设置在应用内完成，启动和保存不再要求使用者操作终端。先照顾当前使用环境，打包方式与更多平台的支持随实际需要确定。

**让 Agent 更有眼光。** 找到具体的人与时刻，分清材料说了什么、自己推断了什么，敢于放下牵强的角度。创意要有品牌参与的理由，写出的正文要能读，而不只是描述“可以做一个什么”。

**把继续合作做顺。** 打开昨天的企划，知道哪些方向已经留下、哪些被放下、稿子为什么改过。补一份材料或说一句反馈，就能接着推进。品牌资料积累真实条件和有原因的好坏例子，一次否决不自动变成永久规则。

这几件事一起推进，不以堆满功能作为完成标志，也不把网页 Demo 原样套进一个窗口就当作最终 App。

## 网页端：保留入口，稍后再谈上线

已有网页继续用于本地试用和交互探索。后续让网页承接同样的企划工作方式，便于在适合浏览器的场景中使用。

在线访问、跨设备接续与多人协作是否需要、先做哪项，由实际使用决定。当前不承诺上线日期，不为部署提前扩建账户、协作或运营系统。

## 每次迭代，由真实作品带路

| 遇到的问题 | 接着改什么 |
|---|---|
| 观察停在热词，换个品牌名也成立 | 补具体作品和反例，改善品牌判断 |
| 好角度缺关键现实条件 | 寻找能回答这个问题的来源或工具 |
| 改稿只换词，没有改变做法 | 改善对反馈、约束和创意机制的理解 |
| 用户反复解释同一项品牌取舍 | 让人方便地把有用经验整理进品牌底稿 |
| 打开、找稿、补材料太费劲 | 改善 App 的启动、作品组织和输入体验 |

我们用 Codex 阅读实际作品和修改过程，再改善这个特化 Agent 的方法与工具，带回下一份企划中尝试。当前不建设自动评分、自我改写或多角色编排平台。

## 最终想留下的东西

打开 App，一张有记忆的企划桌面：材料在，没想完的问题在，上次留下的好角度也在。你和 Agent 可以把一个模糊念头一路推到有依据、有表达、能带进会议的作品。

网页端延续同样的合作方式。无论从哪里进入，值得不断回来的理由都是作品变好了，也越来越懂得彼此的取舍。
