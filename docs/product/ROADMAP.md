# Brand Radar 第一版开发计划

更新日期：2026-09-01

## 交付目标

五个工作日内完成一个可由企划人员实际试用的品牌驱动默认场景：先选择通用品牌档案或回答六问形成定制档案，再用真实模型 API Key 读取咖啡品类 Replay / 公开材料，逐轮选择调查与营销能力，产出情报流、未来 30 天关键节点、关键词、三条 Brief 和本地 HTML 周会稿，最后停在人工采用、退回或补齐来源前。

开发顺序以业务闭环为准。先让同一批材料经过真实 Agent 得到一份可复核结果，再做页面；页面不另写静态结论。

## 第一天：把业务样本准备成可工作的观察包（骨架已实现）

- 确定 2026 年 9 月 7 日至 13 日的瑞幸默认观察设置。
- 准备材料清单，补齐来源、日期、链接或文件位置、来源类型和版本关系。
- 至少包含一组重复材料、一组新旧版本、一项无关或过期内容、一项信息不完整的内容和一个风险节点。
- 人工先做一份期望结果，确认合并边界、优先级和三条 Brief 的证据关系。

完成标志：企划人员不看代码也能读懂观察包，并能指出每条期望结论来自哪里。

## 第二天：打通真实 API 的完整链路（已形成 Day 1–2 周会骨架）

- 增加 `brand_radar_weekly` 当前场景，只读取本次观察包。
- 增加“真实模型必需”开关；缺 Key、错误 Key或模型失败时明确停止。
- 跑通读取、版本核对、事件合并、优先级判断、日历、关键词和 Brief 生成。
- 默认停在人工复核前，不调用发送、发布、投放或预算工具。

完成标志：使用一个用户授权的测试 Key 跑出完整结果，三条 Brief 都引用存在的情报卡；更换一个关键词后结果发生合理变化。

阶段判定：观察包、单场景 CLI、专用校验、严格 API 开关、人工复核边界和同源 HTML 周会稿已实现。当前真实主演示已升级到品牌驱动逐轮流程：通用 `BRAND.md`、四轮选择、三个本地调查动作、7 卡 / 3 Brief、`awaiting_human_review`，错误 Key 明确失败且不降级 Mock。它证明可运行单 Agent 演示骨架成立，但 Brief 仍是企划雏形，来源包无图像素材或实时抓取，未来 30 天是关键节点而非逐日内容，因此不能称为完整成熟或自治营销产品。

## 第三天：加入品牌起点与逐轮企划判断（演示骨架已实现）

- 增加通用 `BRAND.md` 和六问建档入口；逐题可跳过，首次建档全部跳过时不创建本机档案。
- 增加信号筛选、品牌契合、Brief 转译三项营销能力，让 Agent 每轮只选择当前需要的一项。
- 让 Agent 查看当前反馈后决定继续调查或开始成稿，并把每轮理由写入可复查结果。
- HTML 周会稿显示通用 / 定制品牌起点、本次实际使用能力，以及“为什么继续 / 为什么停止”，仍只保留一个 Agent 思路区。
- 保持结果停在人工复核；不加入发送、发布、投放或预算动作。
- 全量 100 项测试通过；真实 `deepseek-v4-flash` 运行约 29.5 秒完成四轮选择和最终成稿。

完成标志：企划人员能看到“品牌起点 → 当前信号 → 所选能力 → 本地反馈 → 继续调查 / 开始成稿 → 人工复核”的完整链。当前已达到演示骨架要求。

## 第四天：把六问接到轻量 GUI / chat

- 复用现有六问状态机，不在界面层另写一套品牌建档逻辑。
- 支持逐题回答、跳过、返回修改和最终确认，清楚提示当前使用通用还是定制档案。
- 继续让已校验 JSON 和同源 HTML 承担事实交付；chat 先承接建档、解释和追问，不复制一套静态结论。
- 用一份真实定制品牌档案运行默认观察包，对比通用档案的调查路径、优先级与 Brief。
- 保持来源、真实模型 / Mock 和人工控制点可见，不先扩成复杂 Dashboard。

完成标志：同一六问在轻量 GUI / chat 中可完成，定制档案真实进入逐轮判断，并出现可解释的结果差异。

## 第五天：按真实业务走一遍

- 分别用通用档案和一份真实定制档案跑周企划演示。
- 验证错误 Key、断网、缺材料、无效引用和来源打不开等失败路径。
- 从结果生成完成后计时，确认新用户能在三分钟内找到重点、查看依据并处理一条 Brief。
- 在本机浏览器完成 HTML 视觉检查，补充一张真实页面截图、最小启动说明和 Mac Mini 回读记录。
- 只有以上通过后，再决定是否迁移早期目录。

完成标志：PRD 的业务验收逐项有真实运行证据；仓库状态与 README 表述一致。

## 仓库整理顺序

当前先保持运行依赖稳定：

- 保留 `run.py`、`framework/`、`v3_agent/tools.py` 和 `scenarios/tools_real.py` 的现有位置。
- 新增当前 Brand Radar 场景、Replay 材料和本地 HTML 周会稿；交互 Dashboard / chat 作为下一阶段候选。
- 保留根目录通用 `BRAND.md`；本机 `memory/brand/BRAND.md` 与 `outputs/` 一样不提交、不跨机器复制。
- README 只把新场景作为当前产品，把 V1-V3 和旧场景标为早期探索。
- 新入口通过后再做单独迁移提交；迁移时同时更新 import、命令和最小回归测试。

## 何时停止扩张

出现下列情况时回到本周唯一场景，不继续加设施：

- 为了多品牌、多 Agent 或实时抓取推迟真实 API 全流程。
- 页面开始产生与 Agent 输出无关的静态结果。
- 为了目录美观移动仍被执行器依赖的文件。
- 为了展示复杂度增加数据库、账号、调度、向量库或自动外发。
- 同一失败在依赖安装、构建或模型接入上重复两次仍没有新证据。
