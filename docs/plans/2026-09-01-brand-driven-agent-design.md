# 品牌驱动的最小营销 Agent 设计

## 这轮要让用户感受到什么

Brand Radar 不再只从“本周有哪些材料”开始，而是先知道“这个品牌是谁”。

首次使用时，用户可以：

1. 直接跳过，使用仓库内的通用 `BRAND.md`；
2. 回答 6 个递进问题，形成一份本机品牌档案；
3. 以后重新进入同一向导，只更新发生变化的答案。

周企划运行时，Agent 必须读取实际生效的品牌档案，再观察 Replay 材料。它每次只选择一项营销技能和一项本地调查动作，读取反馈后才决定下一步；最多调查 3 次，随后生成企划并停在人工复核。

## 用户路径

```text
打开 Brand Radar
  -> 跳过：使用通用 BRAND.md
  -> 或回答 6 问：保存本机品牌档案
  -> 提出本周营销目标
  -> Agent 读取品牌档案、运行规则和观察包
  -> 选择一项营销技能与一项调查动作
  -> 读取反馈，再决定继续或开始企划
  -> 生成情报卡、30 天日历、关键词、3 条不同 Brief
  -> 停在人工复核
```

现在先交付终端入口和可复用的问答状态机。未来 GUI 只需要逐题调用同一状态机，不需要重写品牌逻辑。

## 文件分工

| 文件 | 面向谁 | 只负责什么 |
|---|---|---|
| `BRAND.md` | 品牌/企划人员 | 通用品牌框架和默认答案 |
| `memory/brand/BRAND.md` | 当前本机用户 | 六问后形成的品牌档案，存在时优先使用 |
| `agent/AGENTS.md` | 产品运行时 | 单 Agent 的工作方式、循环和停止规则 |
| `skills/brand-radar/*/SKILL.md` | 营销 Agent | 信号筛选、品牌契合、Brief 转译三种能力 |
| 根目录 `AGENTS.md` | Codex 等开发工具 | 继续保留开发规则，不作为产品提示词 |

用户品牌档案默认留在已被 `.gitignore` 覆盖的 `memory/`，避免把未公开品牌信息意外提交。每次结果会记录实际使用的品牌档案模式、文件和指纹，便于复查。

## 六个品牌问题

1. 品牌希望被怎样记住？
2. 最重要的人是谁，他们在什么场景下需要品牌？
3. 品牌承诺是什么，哪些事实能让人相信？
4. 品牌应该像怎样的人说话，绝不能像谁？
5. 面对热点和竞品，什么机会值得跟、什么机会宁可错过？
6. 哪些表达或动作绝不能做，什么情况必须交给人确认？

后一个问题会引用前面的回答，形成短对话而不是静态表单。空答案使用通用默认值；全程跳过不写本机档案。

这六问吸收了公开品牌实践中“稳定的品牌声音、随情境变化的语气”“明确受众、价值与正反例”的共识，但只保留会影响营销判断的部分：

- Mailchimp Voice and Tone: https://styleguide.mailchimp.com/voice-and-tone/
- Shopify Brand Voice: https://www.shopify.com/blog/brand-voice

## 三个原生营销技能

- `signal-triage`：判断本周跟进、继续观察、主动避开或信息不完整。
- `brand-fit`：用 `BRAND.md` 判断某个信号是否真正适合这个品牌，而不是“热点都能追”。
- `brief-distillation`：把已核材料转成 3 条受众、时机和创意逻辑不同的 Brief。

Agent 在每轮决策中明确选择一个技能。启动时只看到技能目录；选择后，完整技能说明进入后续工作记忆和最终生成上下文。

## 最小循环

```text
目标 + BRAND.md + 观察材料 + 已有反馈
  -> investigate：选择一个 skill + 一个本地动作
  -> 执行动作并追加反馈
  -> 回到模型重新判断
  -> generate：说明为什么信息已经够用
```

限制：

- 至少完成 1 个本地调查动作；
- 最多完成 3 个动作；
- 同一工具和参数不得重复；
- 每轮只能新增 1 个动作；
- 最后一轮必须明确选择开始企划；
- 企划结果校验失败仍只允许修正 1 次；
- 任何失败都不得降级 Mock 或留下半份正式结果。

JSON 结果升级到 `schema_version=1.2`，增加可回放的逐轮 `decision_log` 和品牌档案摘要；旧 `1.0/1.1` 结果仍可读取。HTML 用业务语言展示“先看了什么、看到什么、为什么又查下一项、用了哪种营销能力”。

## 本轮不做

- 不开发 GUI，只保证核心问答状态可以被 GUI 复用；
- 不做多 Agent、Dify 迁移、数据库、账号系统或向量知识库；
- 不做实时抓取；
- 不自动发送飞书、发布、投放或修改预算；
- 不把一次真实运行生成的模型总结自动写成长期品牌事实。

## Demo 成功画面

1. `python run.py --brand-setup` 能完成六问、逐题跳过或整体跳过，并原子保存品牌档案。
2. 不运行品牌向导也能直接使用通用 `BRAND.md`。
3. 一条真实 Key 命令能看到 Agent 逐步选择营销技能和调查动作，生成 JSON 与 HTML。
4. HTML 明确展示本次使用的是通用还是定制品牌档案，以及 Agent 的调查路径。
5. 错误 Key 明确失败，没有 Mock、JSON、HTML 或临时文件。
